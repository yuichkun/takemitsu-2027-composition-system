# パレットの手引き

antara のパレット（`sketches/antara/palette/`）にスケッチを足す人（Claude、サブエージェント、Codex）が、作る前に必ず読むもの。
2026-09-29、余湖さんと確かめたコツを書いた。ここに書いていないことで迷ったら、前提（[`docs/antara/premise.md`](../../../docs/antara/premise.md)）と音の原則（[`docs/antara/sound.md`](../../../docs/antara/sound.md)）に戻る。

## 1. 目指しているもの

antara（余湖雄一さんの管弦楽曲、武満徹作曲賞 2027 に応募する）で挑むのは、**調性感は音程の関係の中に「結果として」生じる**ということを、曲として成り立たせること。
調性は目的でも敵でもない。避けるのでも戻るのでもなく、関係の結果として現れ、また消える。

「あいだ」は、二つのものに挟まれた第三のものではない。**二つを分ける切れ目そのもの。** 前提はこれを三つに縮めている。

1. 関係（切れ目）が先にあり、項は後から付く名前である
2. その名前は、立つ位置で変わる
3. どの項も立っていない切れ目は、欠けではなく、新しいものが定義される場所になる

## 2. 音の原則（要約。正本は sound.md）

- **間**: 二つの音のあいだ。四分音の何個分かで数える（コードでは半音単位、四分音は .5）。0（同じ音）も間。四分音は間の atom で、それより細かくは使わない
- **セット**: どの間を、いくつずつ持つか
- **規則**: セットから、次にどの間を取り出すか。決まった順に回すのも、流動的に変えるのも同じ「規則」
- 音の並びは、起点（最初の 1 音、立ち位置）に、規則がセットから取り出した間の列を足したもの。セットは曲の中で変わってよく、その変化の物語が composition
- **時間の軸も同じ形。** 間は鳴り始めの間隔。拍を割らずに、起点から足していく。atom は素数の仲間ごとに一つ: 2（16 分）、3（3 連 8 分）、5（5 連 16 分）。7 は使わない。
  一つの線はある区間のあいだ一つの仲間の上で足し、仲間を替えるのは仲間どうしの格子が重なる所（拍、小節線）だけ。違う仲間は違う線に同時に置ける
- **二つの格子**（提案中。夜のあいだは試してよい見方）: 四分音の格子は、四分音ずれた二つの半音の格子。.5 の付く間は線をもう一方の格子へ移し、付かない間は同じ格子に置く。
  固定の音の楽器（ハープ、ピアノ、チェレスタ、鍵盤打楽器）は起点の格子だけ。四分音低く調弦したハープやピアノ（`name` に "tuned ¼ tone low" と書く）はずれた格子だけ。弦・木管・金管はどちらも出せる
- **時間の間の 0**（原則では未決。試してよい）: 時間の間が 0 の並びは、同時に鳴る音（和音、縦の線）

## 3. A と B

- **A（一つの課題）**: 一つのことだけを、わかりやすく試す。複合的にしない。方法そのものが使えるかを、混じりけなく判断するため。
  楽器は、その課題が一番はっきり聴こえるものに絞る（音高の課題なら音色を揃える、など）。30 秒〜1 分 15 秒くらい
- **B（使ってみた例）**: A の方法（パレットの A、または `ideas/` の lines・two-grids・running の仕組み）を、実際の場面で使う。
  中編成〜大編成で、展開を作りながら。具体的な使い道を、音楽のアイデアとして拾うため。複合的でよいが、どの A を使ったかを必ず書く。1〜2 分くらい
- **スケッチの違いは、仕組みの違い。** 一つの仕組みの中でつまみを変えた版を並べない。つまみは、その仕組みを決める最小限にする

## 4. コツ（やること）

1. **作る前に、問いを原則の言葉に言い直す**（間・セット・規則、格子、仲間、立ち位置、間の 0）。言い直せないうちは作らない。
   例: 「縦の線が横の線になる」は「時間の間が 0 の並びが開く／音程の間が 0 の並びへ閉じる」と言い直せた
2. **素材は関係。** 名前の付くもの（和音の種類、調の感じ、拍、音色）は結果にする。
   値は構造の理由（間の大きさ、個数、.5 の有無、対称、端、二組に分ける、など）で選ぶ
3. **名前の立っていない所へ向かう。避けない。** 四分音は最初から格子に入れる。仮の値にも .5 の付く間を入れる
4. **比喩や楽器から始めるときは、それを原則の中の構造に写してから作る。** 色（楽器の選び方）が関係から決まるようにする。
   例（ガラスの和音）: 二つの格子を二枚の面に、一つの格子しか出せない楽器をその面でしか光らない鏡に写した。
   例（下の間が付ける音色の名前）: 各声の色を、その声の下の間が狭いか広いかで決めた
5. **仕組みどおりに鳴っていることを数で確かめる**（崩れ方の拍、別々に鳴る所の数、動いた声の数、格子の移り、など）。カードの「事実」に書く
6. **聴きどころを先に書く。** 何を聴けば仕組みが聴こえるか
7. **広げる段で狭めない。** 弾きにくさ（四分音、音域の端、速さ）で候補を削らない。気になる所は「作曲の段で考える点」としてカードに残す

## 5. やってはいけないこと（どれも実際に余湖さんを深く失望させた）

- **値や札を名前で選ぶ・正当化する**: 三和音、調、旋法、5 度圏の幅、音階、既知の様式（「〜風」）、平均律の音名で選ばない。2・5・7（余湖さんの好み）を仮の値に置かない
- **調性を狙う、または避ける**: 「調性感が出て崩れる」を目標にしない（前提が退けた折衷）。調性を避けるための操作もしない
- **安全に倒す**: わからない所で、四分音を外す、響きを無難にする、既知の型に寄せる
- **映画音楽の型**: 刻み → 盛り上げ → ユニゾンの一撃、のような盛り上げ方の型
- **四分音を効果として置く**: 揺れ・うなり・「微分音らしさ」を聴かせるために置かない。四分音は分解能のためだけ
- **コンセプトの具体でこじつける**: マラッカ海峡、Nusantara、1824 年の線、マレー語などを、仕組みや値の理由にしない（例: 「海峡をイメージした点描」は禁止）。使ってよいのは前提の三点（抽象）まで
- **A を複合的にする**: 二つ以上の仕組みを A に入れない
- **説明を上から読めなくする**: 言葉を定義せずに使う。番号や記号で物を指す（「Q3」「R2」など）

## 6. 作り方（技術）

### 置き場所

- A: `sketches/antara/palette/a/<軸>-<名前>/`（軸は `pitch-`、`time-`、`texture-`。名前は英語の短いスラッグ）
- B: `sketches/antara/palette/b/<名前>/`
- 中身: `sketch.ts`、`values.json`（中身は `{"values": {}, "presets": {}, "touched": []}`）、`README.md`（カード）、走らせると書かれる `<名前>.json`（楽譜）
- **自分のフォルダの中だけを書く。** `common.ts`、`trade.ts`、`between.ts`、一覧の `README.md`、ほかのスケッチ（特に `values.json`）には触らない。
  必要な道具は自分のフォルダの中に書く（`sketch.ts` の中か、同じフォルダの別ファイル）
- **git add / commit はしない**（記録とコミットはメインのセッションがやる）

### sketch.ts の形

`knobs` と `score(values)` を export する。見本: [`a/pitch-trade-places/sketch.ts`](./a/pitch-trade-places/sketch.ts)、[`b/colour-by-between/sketch.ts`](./b/colour-by-between/sketch.ts)、[`../ideas/lines/`](../ideas/lines/README.md) の 8 本、[`../ideas/two-grids/sketch.ts`](../ideas/two-grids/sketch.ts)（グリッサンド、四分音低いハープ）。
ファイルの頭に、何をするスケッチかを英語のコメントで書く（ほかのスケッチと同じ書き方）。

- つまみ（`src/sketch/knobs.ts`）: `betweenSet`（間のセット。音程は `unit: "st"`, `step: 0.5`、時間は `unit: "atoms"`, `step: 1`）、`number`、`choice`、`pitch`（"C3"、"E+4" のように書ける。値は MIDI 番号）、`toggle`、`text`
- 共通の道具: `sketches/antara/between.ts`（`TICKS` = 1 拍 60、`atomOf(family)` = 2: 15, 3: 20, 5: 12 tick、`familyOf`、`FAMILY_OPTIONS`、`drawer`、`time`）、
  [`common.ts`](./common.ts)（`stream`、`stack`、`fold`、`gridOf`、`assign`、`divisi`（弦の分奏）、`inOrder`、`numberFromTop`、`curve`（強弱）、`note`、`part`、`scoreOf`、`Player`）、[`trade.ts`](./trade.ts)
- 楽譜の約束: `src/score/types.ts`。時間は 4 分音符単位（`time(ticks)` で分数に）。音高は実音の MIDI 番号で、四分音は .5。強弱は 0（niente）〜8（fff）の曲線。
  `gliss: true` で次の音へ滑る。`technique` は `src/instruments/techniques.ts` の語彙（pizz、sul-pont、sul-tasto、flautando、harmonic、tremolo、con-sord、flutter、muted、roll、bowed、damped など）
- 楽器の id と音域: `src/instruments/catalog.ts`。弦のセクションの人数（Vn I 16、Vn II 14、Va 12、Vc 10、Cb 8）を分奏の合計が超えないこと（`players`）
- 再生は BBC Symphony Orchestra の音。ハープの倍音の音はない（ふつうの撥弦で鳴る）。バス・トロンボーンはセクションの音だけ
- 小節は 4/4 のまま（`scoreOf`）。聴こえる拍は間から結果として生じる

### 確かめる

```sh
vp node src/sketch/check.ts sketches/antara/palette/<a|b>/<名前>
vp check --fix sketches/antara/palette/<a|b>/<名前>
```

- `check.ts` は楽譜を書き、プレビューと同じ読み方（記譜、再生の計画）で読んで、長さと警告を出す。**警告 0 で通るまで直す**
- `vp check --fix` は整形と型と lint。エラー 0 で通す
- 仕組みどおりに鳴っているかは、書かれた楽譜（`<名前>.json`）を読んで数える（小さな python や node の一回きりのスクリプトでよい。repo には残さない）

### カード（README.md）の形

```md
# A · <日本語の名前>      （B なら「# B · …」）

- 状態: 試し中（<日付>）。パレットの見方は [`../../README.md`](../../README.md)
- 作るもの: [`sketch.ts`](./sketch.ts)
- （B なら）使っている A: <リンクと名前>

## 一つの課題（B なら「何をしたか」）
## 仕組みと聴こえ方（言葉は初めて使う所で定義する。仮の値をなぜ選んだかを構造の理由で）
## 聴きどころ
## 楽器
## つまみ
## 事実（長さ、check の結果、数で確かめた仕組み）
## 作曲の段で考える点（いまは狭めない）  ← あれば
## 聴いてどうだったか
（余湖さんが聴いたら書く）
```

カードは日本語で、フラットな書き言葉。余湖さんが上から読んで分かるように。
