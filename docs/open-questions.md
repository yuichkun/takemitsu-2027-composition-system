## 決着している前提

- **応募資格（年齢）を満たしている。** 2027年度への応募が成立する
- **四分音までを使う音楽にする。** スペクトル解析的なアプローチと、
  限定された音程を組み合わせで数学的に探求するアプローチを想定
- **恣意的なメロディを入力するケースは少ない。**
  素材は解析と数学的構成から来るのであって、即興の採譜からは来ない
- 手法の系譜は、**リゲティ／クセナキスのアルゴリズミックな手法、あるいはミュライユ／グリゼーの
  スペクトル手法**。余湖さんは Opusmodus での作曲経験を持つ
- **データの最小単位は音符ではなく、より上位の単位にする**
  （[`decisions/0005`](./decisions/0005-gesture-as-primitive.md)）。
  「ジェスチャー」という概念と名前は、設計の中で別の概念に置き換えてよい
- 手持ちは **Komplete 14** 系。ただし特殊奏法と打楽器が決定的に重要なため、
  別の音源を購入する選択肢が開いている（→ [Q1](#q1)）
- **即時プレビューは不要。** 高品質オフラインレンダのみでよい
- **規定リンターは作らない。** 提出前に人間と AI で一度点検する
  （[`decisions/0009`](./decisions/0009-no-linter.md)）

# 工学の論点

## Q12

### 四分音を MusicXML でどう表現し、Sibelius にどう渡すか

**四分音を使うと決まった時点で、これが最大の技術的リスクになった。**
記譜と再生の両側で、通常の半音階を前提とした経路が壊れる。

**記譜側も再生側も、四分音そのものは決着した。**

- 記譜: MusicXML の `<alter>` に小数値を書けば Sibelius 標準の四分音記号が付く
  （[`decisions/0011`](./decisions/0011-quarter-tone-notation.md)、
  実測は [`research/sibelius-musicxml-import.md`](./research/sibelius-musicxml-import.md) 2.5節）
- 再生: ノートごとのピッチベンド、1声部1MIDIチャンネル
  （[`decisions/0010`](./decisions/0010-pitch-bend-quarter-tones.md)）

**残っている内容**

- 移調楽器・小節内の臨時記号規則・持ち替えとの組み合わせ（第2回テスト `qt-06b` / `qt-07b` / `inst-02`）
- 取り込みで落ちる記譜（ハーモニクスの○、Bartók pizz.、+、niente、延長破線、奏法遷移の線、
  トリルの補助記号、波線、持ち替え）を `§` マーカー + ManuScript プラグインで置く経路の実機確認
  （`sibelius-plugins/`、テスト `fix-01`）

## Q1

### 使用するオーケストラ音源

**決める内容**

- 手持ちの Komplete 14 系で足りるか、別途購入するか
- 購入する場合、何を買うか

調査は完了した。詳細と出典は
[`research/orchestral-libraries.md`](./research/orchestral-libraries.md)。

**調査で判明した最重要の事実:** 四分音を出す手段として使えるネイティブなチューニング機構は
**どの音源にも存在しない**。全部ノートごとのピッチベンドに落ちる
（[`decisions/0010`](./decisions/0010-pitch-bend-quarter-tones.md)）。
したがって**音源の選定はホストの実装を止めない。**

**僕の推薦:** 四分音は物理モデリング系、特殊奏法と打楽器はサンプル系という分業。
**打楽器は四分音を必要としない**ので、両者は競合しない。

| 役割 | 製品 | 価格 |
| --- | --- | --- |
| 音高のある楽器の主力 | SWAM Solo Strings / Woodwinds / Brass | $339 / $699 / $599 |
| 打楽器 | Spitfire Symphonic Extras | **$99** |
| 弦の特殊奏法の色 | LCO Strings | $349 |
| 打楽器を厚くするなら | ARO Metal Percussion | $449 |

**決める内容**

- この分業を採るか。採るなら、どこまで買うか（木管 $699 が最も高い）
- **SWAM のヘッドレス動作**が確認できなかった場合の代替をどうするか
- VSL と Orchestral Tools が未調査のまま。調査を再開するか

**買う前に検証すべきこと**（15日トライアル）

1. **ヘッドレスホストで SWAM の Core Assistant / Software Center 依存が邪魔しないか。**
   ネットを切った状態でレンダできるか。**これが通らなければ推薦が崩れる**
2. ピッチベンドで作った四分音の音色が許容できるか（金管はリップテンションとしてモデル化される）
3. String Sections で奏者ごとに個別ピッチを与えられるか

## Q6

### 内部表現の言語とスタック

**決める内容**

- 作曲コードを書く言語
- ビルド・実行の基盤
- ジェスチャーの表現形式（型で持つか、データで持つか、DSL を作るか）
- **音高の表現。** 四分音を扱うので、半音単位の整数では足りない
  （セント値か、有理数か、24平均律の整数か）

**僕の見立て:** AI が編集主体として入れることが要件なので、
読みやすく、diff が意味を持ち、型で誤りが止まることが効く。
音高表現は最初に決めておかないと後から全体に波及する。

余湖さんが Opusmodus の経験を持つことは、この論点の参照点になる。
Opusmodus の OMN 表記は音価・音高・強弱・奏法を1つの列の中に並べて書く形式で、
音符より上位の単位（[`decisions/0005`](./decisions/0005-gesture-as-primitive.md)）を
テキストとして読み書きする実例になっている。
**作曲コードの読み心地を OMN に寄せるか、別の形を採るか**も、ここで決める内容に含める。

# 感性の論点

## Q13

### 個人の声をどこに宿すか

**素材が解析と数学的構成から来るなら、[規律1（素材の出自）](./proposal.md#規律1--素材の出自を記録する)
の前提が変わる。** 出自は「どの即興か」ではなく「どの解析・どの構成・どのパラメータか」になる。

そして審査員が繰り返し指摘している落選の典型
（[`research/takemitsu-award-2027.md`](./research/takemitsu-award-2027.md)）と、
正面から向き合う必要がある。

**両方の読みが成り立つ**

| 読み | 内容 |
| --- | --- |
| **危険側** | スペクトル的・微分音・テクスチュア主体は、ヴィトマンが「複雑で微細に区別されたテクスチュア」と呼んで、その背後に個人の声が聞こえないと言った当のもの。この20年で最も一般化した現代音楽の語法でもある |
| **有利側** | 「**限定された**音程を組み合わせで数学的に探求する」は、密度の高いテクスチュアとは逆。素材を絞って徹底的に扱うのは、近藤譲が評価し、ターネジが「明瞭さ」と呼んだものに近い |

**決める内容**

- 声をどこに宿すか。素材か、形式か、選択の仕方か
- 何を「自分でなければこうしない」判断として意識的に置くか

**僕の見立て:** 素材が数学的に導かれるなら、**声は「何を選ばなかったか」と
「どう時間に配置したか」に宿る**ことになる。つまり形式と選択。
これは [規律3（形式は手で引く）](./proposal.md#規律3--形式は手で引く)の重要度を上げる。

## Q8

### 奏法の語彙をどう決めるか

演奏マップの整備量は `使用楽器数 × 使用奏法数` に比例する。
同時に、限定された語彙を明確な意図で使い分けることは、
審査員が批判している「一様に高密度で匿名的なスコア」の正反対にある。

**決める内容**

- この曲で使う奏法を何にするか
- どこまで絞るか。絞らない選択もありうる

音源の選定（[Q1](#q1)）と相互に効く。使いたい奏法が決まれば音源の要件が決まり、
音源が決まれば使える奏法が決まる。

## Q9

### 編成をどう決めるか

規定の上限内で、実際に何を使うか。

**決める内容**

- 使う楽器と人数
- 打楽器4奏者に何を割り当てるか（持ち替えの物理的成立を含む）
- キーボード2奏者を使うか
- 「その他の管楽器1」の枠を使うか

**僕の見立て:** 上限いっぱいを使う必要はまったくない。
ターネジが名指しで批判しているのは、むしろ大編成を常時鳴らす書き方。

## Q10

### 演奏時間をどこに置くか

規定は10分以上20分未満。

| 選択 | 効いてくること |
| --- | --- |
| 短め（10〜13分） | 形式を凝縮できる。ドラマの振幅を取りにくい |
| 中程度（13〜17分） | 境界から遠く安全 |
| 長め（17〜19分台） | 大きな時間設計ができる。境界に近く、テンポ解釈で上限を割るリスク |

## Q11

### 形式（ドラマの曲線）をどう表現するか

[Q13](#q13) により、**この論点の重要度が上がった。**
素材が数学的に導かれるなら、作曲者の判断が最も濃く現れるのは形式の側になる。

**決める内容**

- 時間設計を何で持つか（区間の列か、連続曲線か、注釈つきタイムラインか）
- 密度・レジスター・緊張度などの軸を何本持つか
- 引いた曲線が生成をどう拘束するか（強制か、参照値か）
