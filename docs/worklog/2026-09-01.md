## 観測したこと

### ★四分音の手段は、調べた結果すべてピッチベンドに収束した

これが今回いちばん大きい発見で、しかも当初の想定と違っていた。

- **音源内蔵のマイクロチューニングは使えない。**
  SWAM も Sample Modeling も **12ピッチクラス単位でオクターブ反復**する構造で、
  同一オクターブ内に C と C↑ を併存させられない。
  どちらもアラブ・マカーム（E と B を -50 セント）用に設計されている。
- **MTS-ESP を挟む意味がない。** 公式ページ自身が、ネイティブ非対応のプラグインには
  「MPE, MTS SysEx or **MIDI pitch bend**」で落とすと書いている。
  MIDI を自前生成する本システムでは中間層が増えるだけで、
  ベンドレンジを最適化できない分むしろ不利。
- **記譜ソフト経由の道も閉じている。** Dorico の微分音メッセージに対応するのは
  NotePerformer / HALion / Pianoteq のみで、Kontakt・Spitfire・Orchestral Tools・VSL は非対応。
- **NotePerformer は設計が理想的なのに使えない。**
  CC102 でノート単位・セント単位（±63セント）のデチューンを持つ。
  今回調べた中で最良の微分音制御設計だった。
  しかし記譜ソフト以外のホストにロードできない（Steinberg スタッフが明言）。
  バイナリは標準の VST3 として置かれるので、意図的にホストを判別して弾いている。回避手段なし。

**設計上の帰結として、音源の選定とホストの実装が切り離せることが分かった。**
どの音源を選んでも実装は「ノートごとのピッチベンド + 1声部1チャンネル」になる。
音源が決まる前にホストを書き始められる。

### 音源の性格が、想定していた通り二分された

四分音の素直さ（物理モデリング）と、特殊奏法・打楽器の実在感（サンプル）がトレードオフになる。
ただし**打楽器は四分音を必要としない**ので、この2つは競合せずに分業できる。

- **SWAM**: ソロ楽器が**モノフォニック**なので、同時に1音しか鳴らず、
  ピッチベンド1個でそのノートの高さが確定する。チャンネル割り当てのパズルが生じない。
  さらに**キースイッチで制御する全パラメータが CC / NRPN でも制御できる**ため、
  ノート番号空間を汚さずに済む。プログラム制御という一点で条件が非常に良い。
- **Spitfire Symphonic Extras ($99)**: 旧 Symphonic レンジで唯一ディスコンを免れた製品。
  Scraped Percussion 45+奏法（弓・鋸歯・superball・saw blade・waterphone）を最安で覆う。

### 各音源が持つ「意図的なピッチ揺らし」に注意が要る

四分音の精度を出すには明示的に潰す必要がある。見落とすと意図した音程が汚れる。

- Sample Modeling: CC28 random detune / CC32 pitch fluctuation / CC24 dyn→pitch / CC20 が全部既定64
- Aaron Venture: **CC33「Pitch Accuracy」は意図的に音程を外し、0.5〜1.0秒かけて「補正」する。**
  四分音では致命的なので最大値に固定する

### ホスト設計への申し送りが1つ出た

`[文献]` Sample Modeling の FAQ が「バッファサイズ 256 か 512。512超は副作用が出る」と明言し、
**バウンス時も同じだと書いている**。オフラインレンダは大きいブロックを使いがちなので、
**ホストのブロックサイズは設定可能にしておく**必要がある。

  VSL と Orchestral Tools が未調査のまま残った。
  VSL は歴史的に最も奏法数の多いライブラリなので、これは実質的な穴。

  完了した4件（Spitfire / SWAM / Aaron Venture・NotePerformer / Sample Modeling）の
  成果は取れたが、網羅性は欠けている。
