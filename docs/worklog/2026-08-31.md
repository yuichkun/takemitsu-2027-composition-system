## 観測したこと

### 調査で判明した、設計に効く事実

- **譜面審査は審査員本人が行う。** 予備審査委員会は存在しない。
  英語版原文で確認: "The judge will screen the submitted scores and select a certain number of works to be performed."
- **応募数は毎年80〜137、本選進出は例外なく4作品。** 通過率3〜5%。
- **規定違反による不受理が毎年数件発生している。**
  2026年度は116応募中4件、2024年度は104応募中2件。機械的に防げる失敗。
- **審査員が毎年公開している「譜面審査を終えて」の総評で、直近4人が独立にほぼ同じ診断を下している。**
  落ちる典型は「密度が一様に高い、テクスチュア主体の、上手いが匿名的なスコア」。
  これが本調査で最も価値のある発見。
- **シェパード本人の審査方針の表明は存在しない。** 公式ページを生HTMLで直読みして確認。
  彼自身の譜面審査コメントが公開されるのは2026年12月上旬（応募後）。
- 見落としやすい規定を2つ発見した。
  **記譜に使える言語が英・仏・独・伊のみ**（日本語の奏法指示が書けない）。
  **パート譜は不要**（本選ノミネート作の演奏用楽譜は主催者が作成する）。
- **持参が認められている。** 郵送のリスクを取らずに当日持ち込める。

## 前提の確定と、それによる設計変更

余湖さんから回答を受けて、以下が確定した。

- **応募資格（年齢）を満たしている。** 2027年度への応募が成立する
- **四分音までを使う。** スペクトル解析的アプローチと、限定音程の数学的探求を想定。
  **恣意的なメロディを入力するケースは少ない**
- 手持ちは Komplete 14 系。特殊奏法と打楽器が決定的に重要なため、別音源の購入もありうる
- **即時プレビューは不要**
- **規定リンターは too much。** 提出前に人間と Claude で一度点検すればよい
- VST ホストについて、**余湖さんの持ち物や知見を前提にした案は不可**という指摘を受けた。
  Reaper は所持しておらず、JUCE の知見もない。コードを書くのは Claude である以上、
  作業や学習コストを押し付ける構成は成立しない

これを受けた設計変更:

- 四分音を系全体の前提にした（[`../decisions/0008`](../decisions/0008-quarter-tone-native.md)）。
  **音高表現を半音単位の整数にしない。**波及範囲が全層に及ぶため、最初に決める必要がある
- VST ホストを自作のヘッドレス CLI（C++ / JUCE）に決めた
  （[`../decisions/0007`](../decisions/0007-own-headless-host.md)）。
  購入も学習も要求せず、四分音のピッチベンドとチャンネル割り当てを完全に制御できる
- 規定リンターを取りやめ、[`../competition.md`](../competition.md) に提出前の点検表を置いた
  （[`../decisions/0009`](../decisions/0009-no-linter.md)）
- 素材の入口を、鍵盤・録音中心から**解析と数学的構成**中心に組み替えた
- 新しい論点を2つ立てた。**Q12（四分音を MusicXML でどう表現し Sibelius に渡すか）**が
  最大の技術的リスクになり、**Q13（個人の声をどこに宿すか）**が
  素材が数学的に導かれることで重みを増した

## 観測したこと（2回目）

- **構想の外形が、審査員が批判した語法に近い。**
  四分音・スペクトル的・微分音のテクスチュアは、ヴィトマンが
  「複雑で微細に区別されたテクスチュア」と呼んで個人の声が聞こえないと言った当のもの。
  一方で「**限定された**音程を組み合わせで探求する」は密度の高いテクスチュアとは逆で、
  近藤譲が評価しターネジが「明瞭さ」と呼んだものに近い。
  **どちらに転ぶかは執行の仕方で決まる**と見ている。proposal.md 6.2節に書いた

## 失敗したこと（2回目）

- **perl の in-place 編集で proposal.md のエンコーディングを破壊した。**
  `perl -0777 -i -pe` で本文をバイト列として読み、置換文字列だけを `:utf8` で読んだため、
  出力時に元の本文が二重エンコードされた。未コミットだったため git から戻せず、
  **ファイル全体を書き直して復旧**した。
  → 教訓: UTF-8 のファイルを perl で in-place 編集しない。Edit ツールを使うか、
  　 どうしても perl を使うなら `-CSD` でエンコーディング層を揃える。
- 検証に使った `iconv -f UTF-8 -t UTF-8` の終了コードが当てにならず、
  正常なファイルまで BROKEN と報告した。**二重エンコードされた UTF-8 は
  UTF-8 として妥当**なので、妥当性検査では検出できない。
  実際に効いたのは、モジバケ特有のバイト列（`ã` / `Ã` / `ï¼`）を探す方法だった。
