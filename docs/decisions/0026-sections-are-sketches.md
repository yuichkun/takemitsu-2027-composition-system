# 0026. 曲のセクションはスケッチそのものにする（コードも値も共有し、スケッチで詰めて、曲でつなぐ）

- 状態: 採用
- 関係する論点: Q11（形式をどう表現するか）。[0023](./0023-join-sections-from-outside.md) の上の進め方

## 背景

[0023](./0023-join-sections-from-outside.md) で、セクションは別々のコード（今のスケッチそのもの）のまま、曲の一番上でつなぐと決めた。
試しの [`pieces/four-ideas/`](../../pieces/four-ideas/README.md) では、曲の中のフォルダがスケッチのコードを読み込み直していた。
コードは共通だったが、値は曲の中のフォルダに自分の `values.json` を持ち（「My Fav」は写した）、
プレビューも、スケッチを変えたときに、それを使っている曲を書き直さなかった。

余湖さん（2026-09-29 夜）: two-grids のオーケストラ版を、つなぐ仕組みとフルスコアで確かめていきたいので曲にも入れる。
「今後、スケッチの方で精度をあげて、曲の方で繋ぎ方調整、みたいな感じでいける？」

## 選択肢

1. **値は写す**（four-ideas のまま）: 曲の中のフォルダが値を持つ。スケッチで詰めた値は、写し直すまで曲に来ない
2. **セクションをスケッチそのものにする**: 曲の中のフォルダは、どのスケッチかを言うだけ。コードも値もスケッチのもの。スケッチが変わると、使っている曲を書き直す
3. **曲の一番上がスケッチのフォルダを直接読む**: 曲の中にフォルダを作らない。曲の地図やつまみの欄から、そのセクションを開く所がなくなる

## 決定

2 にする。

- 曲の中のフォルダの `sketch.ts` は二行: スケッチを読み込み直す（`export * from "…/sketch.ts"`）と、どのスケッチかを言う（`export const sketch = "../../../sketches/…"`）
- 値はスケッチのフォルダの `values.json` を読み書きする（[`../../src/sketch/run.ts`](../../src/sketch/run.ts)）。曲の中でそのセクションのつまみを変えても、スケッチの値が変わる
- 曲の楽譜の `outline.sketches` に、そうしているスケッチが並ぶ。プレビューは、そのスケッチのつまみを変えたとき、`.ts` を保存したときに、その曲も書き直す
- 区切りの候補（`seams`）もスケッチに書く
- つなぎ方（どこに置くか、どう替わるか、次のつまみに何を渡すか）は曲の一番上で決める

## 理由

- セクションの中身が一か所にだけある。スケッチで詰めたものが、そのまま曲の中で鳴る
- スケッチは一つで聴いて詰め、曲ではつなぎ方だけを見る、という分け方が、フォルダの分け方と同じになる
- 曲の中にフォルダが残るので、地図とつまみの欄からそのセクションを開ける

## 結果と副作用

- スケッチのつまみを動かすと、曲もすぐ変わる。曲を今のまま残して試したいときは、先にスケッチでプリセットに保存しておく
- 同じスケッチを曲の中で二度使うとき、場所ごとの違いは一番上から渡す（`ctx.render` の `values`。前のセクションから値を渡すのと同じ入り口）
- スケッチが読み込んでいるほかのファイル（`pieces/antara/ensemble.ts`、`sketches/antara/between.ts` など）を変えたときは、今までどおり自動では書き直さない
- four-ideas は写した値のまま（試しとして終わったもの）
