# 0010. 四分音はノートごとのピッチベンドで実現する

- 状態: 差し替え済み → [0013](./0013-quarter-tones-by-instance-tuning.md)（BBC SO はピッチベンドを無視する）
- 関係する論点: Q1 / Q12

## 背景

四分音を系全体の前提とした（[0008](./0008-quarter-tone-native.md)）。
MIDI 射影が、意図した高さを実際に音源で鳴らす手段を持つ必要がある。

理論上の手段は複数ある。どれが実際に使えるかは音源側の対応で決まるため、
調査した（[`../research/orchestral-libraries.md`](../research/orchestral-libraries.md)）。

## 選択肢

| 案 | 中身 | 調査結果 |
| --- | --- | --- |
| A. 音源内蔵のマイクロチューニング表 | 音源の機能でスケールを定義する | **使えない。**SWAM も Sample Modeling も**12ピッチクラス単位でオクターブ反復**する構造で、同一オクターブ内に C と C↑ を併存させられない。アラブ・マカーム用に設計されている |
| B. MTS-ESP（ODDSound） | チューニング標準を挟む | **意味がない。**公式ページが、ネイティブ非対応プラグインには「MPE, MTS SysEx or **MIDI pitch bend**」で落とすと明記。MIDI を自前生成する本システムでは中間層が増えるだけ |
| C. Scala / MIDI Tuning Standard | 標準フォーマットで送る | 主要なオーケストラ音源に対応が見当たらない |
| D. MPE | ノート単位の表現 | SWAM ソロ楽器はモノフォニックで MPE の恩恵がない。サンプル系も対応が薄い |
| E. VST3 Note Expression | ホストからノート単位で送る | Dorico が採用している方式だが、対応するのは NotePerformer / HALion / Pianoteq のみ。**Kontakt、Spitfire、Orchestral Tools、VSL は非対応** |
| F. NotePerformer の CC102 | ノート単位・セント単位のデチューン（±63セント） | **設計は理想的だが使えない。**NotePerformer は記譜ソフト以外のホストにロードできない（Steinberg スタッフが明言）。回避手段なし |
| G. ノートごとのピッチベンド | 発音の直前にベンド値を置く | すべての音源で動く。チャンネル単位メッセージなので声部の分離が必要 |

## 決定

G を採る。**ノートごとにピッチベンドを置き、1声部を1MIDIチャンネルに割り当てる。**

実装方針:

- ベンドレンジは**狭く設定する**。±2半音なら約 0.03セント/step の分解能が得られる
  （±48半音だと 0.7セント/step まで落ちる）
- ノートオンの直前にベンド値を置き、そのノートの高さを確定させる
- 音源が持つ**意図的なピッチ揺らし機能を無効化する**
  （Sample Modeling: CC28 / CC32 / CC24 / CC20、Aaron Venture: CC33 を最大値に固定）
- ホストのブロックサイズを**設定可能にする**（Sample Modeling はバウンス時も 256/512 必須）

## 理由

- **他のすべての手段が、調査の結果、実際には使えないと分かった。**
  内蔵チューニング表は構造的に24音を持てず、標準規格は対応する音源がなく、
  唯一設計の良い NotePerformer はホストにロードできない
- MTS-ESP という業界標準ですら、内部でピッチベンドに落としている。
  つまりこれは妥協ではなく、**この領域における事実上の標準手段**
- SWAM ソロ楽器のように**モノフォニック**な音源なら、同時に1音しか鳴らないため
  「1声部1チャンネル」が自然に成立し、割り当てのパズルが生じない

## 結果と副作用

- **MIDI チャンネルが枯渇しうる。** 声部数が16を超えたら、
  楽器ごとに別のプラグインインスタンス（＝別のMIDIポート）に分ける必要がある
- ピッチベンドを微分音に占有するため、**ピッチベンドを表現手段として使えなくなる**。
  グリッサンドやポルタメントは、音源固有の別の手段で実現するか、
  微分音オフセットに加算する形で設計する必要がある
- `[要検証]` Sample Modeling ではピッチベンドが**エンジン内部でも使われている**
  （ポルタメント、half-valve、falls、doits）。静的オフセットとして占有したとき
  内部生成と加算されるのか上書きされるのかが不明。採用する場合は要検証
- **音源の選定とホストの実装を切り離せる。**
  どの音源を選んでも実装が同じになるため、音源が決まる前にホストを書き始められる
