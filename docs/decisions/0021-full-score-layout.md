# 0021. フルスコアの体裁は慣習に合わせ、MusicXML で運べるものは書き出しで作る

- 状態: 採用
- 関係する論点: 記譜の射影、Q12

## 背景

書き出し（`src/notation/musicxml.ts`）は、楽譜の JSON のパート一つをそのまま段一つにしていた。
並び、括弧、段の名前、二人で一段、ディヴィジ、打楽器、大譜表、楽器ごとの音部記号とオクターヴ記号が、クラシックの慣習的なフルスコアとずれていた。
Sibelius に持っていってから直す量が多いほど、「一旦書き出して Sibelius で完成形を想像する」がやりにくくなる（余湖さん）。

慣習と Sibelius の取り込みは [`../research/score-layout/`](../research/score-layout/README.md) に調べた。
実機でしか分からない所は [`../../verification/sibelius-layout/`](../../verification/sibelius-layout/README.md) のテストで確かめる。

## 決定

**方針**（余湖さん、2026-09-29）: MusicXML で運べるものは全部書き出しで作る。運べないもの（空の段を隠す、テンポと練習番号を下の段にも出す、小節番号の出し方、前付け）は Sibelius での仕上げにする。

決めたこと（余湖さん、2026-09-29。括弧は検討した別の案）:

| 項目 | 決定 |
| --- | --- |
| 二人で一段にするか | 組ごとに、曲全体で一段か二段かを決める（場面ごとに切り替える） |
| ホルンの組 | 1.2 と 3.4（1.3 と 2.4） |
| 持ち替え | 楽器ごとに段を分ける。使わない所は Sibelius で空の段として隠す（奏者ごとに一段で名前を替える） |
| ハープと鍵盤の順 | ハープ → ピアノ → チェレスタ（ハープ → チェレスタ → ピアノ、鍵盤 → ハープ） |
| ティンパニ | 打楽器の括弧に入れる |
| 楽器名 | 英語（イタリア語） |
| トランペット | in B♭（in C） |
| 臨時記号 | その音符にだけ効く。変化のない音にもナチュラルを書く。仕上がりを見て変える可能性がある（小節の終わりまで効く） |
| 用紙 | A2 縦、五線 6 mm、余白 30 mm。印刷の直前に A3 へ縮めても、段とページの区切りは変わらず五線 4.2 mm・余白 21 mm になる（A3 で作る） |
| ディヴィジの段の名前 | 奏者の範囲（Vln. I 1–8）（譜面台で数える、分割の番号） |

慣習どおりにすること（調査から。選択の余地が小さいもの）:

- 並び: 木管 → 金管 → ティンパニと打楽器 → ハープ → ピアノ → チェレスタ → 弦。ピッコロはフルートの上、アルトフルートはフルートの下、
  イングリッシュホルンはオーボエの下、E♭ クラリネットはクラリネットの上、バスクラリネットはクラリネットの下、コントラファゴットはファゴットの下。ホルンはトランペットの上
- 括弧: 家族ごとに太い括弧と通った小節線、同じ楽器の段とディヴィジの段は細い括弧。ハープと鍵盤は波括弧だけで、太い括弧に入れない
- 段の名前: 最初の段は正式名、二段目からは略称。一段に二人いれば番号を必ず入れる。移調楽器は調を入れる
- 二人で一段の書き方: 同じ音なら「a 2」、同じリズムなら和音、リズムが違えば二声（一人目は符尾が上で「1.」、二人目は下で「2.」）、一人だけなら「1.」か「2.」。
  連符の種類が同時に食い違う組、上下が入れ替わる組、同時に違う奏法の組は一段にしない
- ディヴィジ: 二つに分かれるだけで書きやすければ一段で「div.」「unis.」、それ以上は段を分ける
- 打楽器は奏者ごとにまとめる。音高のある楽器は 5 線、ない楽器は 1 線
- 大譜表は、書き手が段を決めていない音を音域で上下に振り分ける
- 音部記号は楽器ごとの慣習の組み合わせにし、加線が 3 本以上続く所でだけ替える。オクターヴ記号は鍵盤・ハープ・鍵盤打楽器だけ（ヴァイオリンの極端に高い所は例外）
- 実音の総譜でも、ピッコロ・シロフォン・チェレスタは 1 オクターヴ下、グロッケン・クロタルは 2 オクターヴ下、コントラファゴット・コントラバスは 1 オクターヴ上に書く。
  バスクラリネットは実音のヘ音記号で書く
- 調号は付けない。作曲者名はどこにも書かない

## 理由

- 審査は紙のスコアだけで行われる。慣習から外れた体裁は、読む手間になり、書き手の経験のなさにも見える
- MusicXML で運べるものを書き出しで作れば、プレビューと Sibelius が同じ形になり、Sibelius での作業が仕上げだけになる
- 選んだ案の理由は、Artifact「スコアの書き方の見直し」と調査ノートにある

## 結果と副作用

- 楽譜の JSON のパートと、スコアの段が一対一でなくなる。二人で一段、ディヴィジの段、打楽器の奏者のまとまりは、書き出しの中で組み立てる
- 実機テストの結果によって、細い括弧、調号なし、用紙、段の名前の ♭ の書き方を変えることがある
- 鍵盤・鍵盤打楽器・ハープの四分音はやめた（[`../antara/sound.md`](../antara/sound.md)）。それを使っている既存のスケッチは、確認で警告が出る
- [0017](./0017-score-in-c.md) の副作用に書いた「MusicXML に `<transpose>` を書かない」は、オクターヴ記譜の楽器にだけオクターヴの `<transpose>` を書くように改めた。
  書かないと、Sibelius は書いた音を鳴る音と読み、オクターヴ記譜の楽器が 1 オクターヴずれる（[`../research/score-layout/sibelius.md`](../research/score-layout/sibelius.md)）
