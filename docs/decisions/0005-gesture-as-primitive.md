# 0005. データモデルのプリミティブをジェスチャーにする

- 状態: 提案
- 関係する論点: Q6 / Q8

## 背景

強弱記号（`mp`、ヘアピン、`cresc.` の楽語）、エクスプレッション、奏法指示を
**一級市民として音楽的に扱う**ことが要求されている。理由は2つある。

- MusicXML に載っていないと、Sibelius 取り込み後の手作業が膨大になる
- 審査員が演奏家上がりであり、生のオーケストラの演奏表現に根ざしている必要がある

この要求は、データモデルの選択で満たされるか失われるかが決まる。

## 選択肢

| 案 | 中身 | 効いてくること |
| --- | --- | --- |
| A. 音符の配列 + アノテーション層 | 音符に強弱・奏法を後付けする | 素直で実装が軽い。**強弱が構造的に二級市民になる。**音符を消しても強弱が残り、AI に「もっと切迫させて」と言っても音高しか動かない |
| B. ジェスチャーをプリミティブにする | 音高輪郭・リズム・ダイナミクス包絡・奏法を、分離不能な1単位が持つ | 強弱と奏法がアイデンティティの一部になる。変形が一括で効く。モデルの設計が重くなる |
| C. MusicXML 相当の構造をそのまま持つ | 記譜の構造を内部表現にする | 輸出が素直。柱3・柱4 の操作に向かず、変形が書きにくい |

## 決定

B を提案する。

さらに**素材・ジェスチャー・配器・スコアの4層に分ける**。
素材と配器を分離することで、同じ素材の配器違いを一括生成して聴き比べられる。

```
素材 material     音高輪郭・リズム・出自。楽器に非依存
  ↓
ジェスチャー gesture  素材 + ダイナミクス包絡 + 奏法。分離不能な1単位
  ↓
配器 orchestration   楽器割当・レジスター・重複・ディヴィジ
  ↓
スコア score        完全に具体化された状態 → 2つの射影へ
```

## 理由

4本の柱すべてに同時に効く。

- **柱1**: 即興から出てくるのは音符列ではなく「形をもった身振り」なので、モデルが発想の形と一致する
- **柱2**: 「この身振りはこの奏法・この強弱で成立するか」という、判断の自然な単位になる
- **柱3**: 変形操作がジェスチャー単位で書ける
- **柱4**: AI に「もっと切迫させて」と言ったとき、**包絡と奏法と音高が一緒に動く**

A を採ると、強弱を一級市民にするという要求が構造的に満たせない。

## 結果と副作用

- 記譜への射影（ジェスチャー → MusicXML）が変換になる。直接対応ではなくなる
- 演奏への射影（ジェスチャー → MIDI + CC + キースイッチ）も変換になり、
  両者を繋ぐ**演奏マップ**という部品が必要になる
- ジェスチャーの粒度をどう決めるかという新しい設計問題が生じる。
  細かすぎれば音符に戻り、粗すぎれば制御できない
- 音符単位の細かい調整をしたくなったとき、モデルが抵抗する可能性がある。
  逃げ道（ジェスチャーを展開して直接編集する経路）が要るかもしれない
