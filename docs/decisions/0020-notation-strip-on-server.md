# 0020. 譜面はサーバで 1 小節ずつ先に描き、段をそろえた横長の 1 本として見せる

- 状態: 採用
- 関係する論点: 書きながら譜面を読むこと。ページ送り、縦に収めること、全画面、飛んだときの速さ、パノラマ、ズーム、低音域の読みやすさ

## 背景

プレビューの譜面（[0016](./0016-preview-in-browser.md)）について、余湖さんから次の要望が出た（2026-09-27）。

- 変な位置でページ送りされる。縦に収まっておらず、下の楽器が見えないことがある
- 全画面で集中して見たい。画面はウルトラワイド（2,560×1,080、等倍）だが、どの画面でも映ること
- 遠くへ飛ぶと、出るまでに時間がかかる
- Sibelius のパノラマのような、切れ目のない横長の見え方も欲しい。ページ表示と切り替えたい
- ズームを自由にしたい
- 低音域が読みにくい。オクターヴ記号で書くべき所がそうなっていない
- 左のサイドバーを Cmd+B で開閉したい

判断基準は音の側（[0019](./0019-fixed-hosts-verified-chunks.md)）と同じ。速さと、バグを生みにくい単純な作りの両方を取る。差分は送らない。メモリとディスクは富豪的に使ってよい。

### 今の作りで分かったこと

コードを読み、20 分のダミー曲（107 パート、112 段、457 小節）で Verovio 5.7.0 を動かして測った。

- **ページという単位がない**
  - 4 小節以下（音符 600 個以下）の「枠」を縦に積み、再生位置の枠が見えるように縦へスクロールしているだけ
  - 244 枠のうち 170 枠が 1 小節。空の段を枠ごとに隠すので、高さもまちまち
  - 再生中は 50 ms ごとに段の上端へ戻すので、下の段を見られない
- **大きさは幅に合わせた固定の 35%**。1 段は数百〜8,000 px の高さになる
- **ブラウザがその場で描いている**（Web Worker 2 本、1 枠 0.1〜2.4 秒）。先読みは上下 800 px だけで、描いたものは窓の幅が変わると捨てる
- **低音楽器の向きが逆だった**。コントラバス、コントラファゴット、バスクラ、バスフルート、コントラバスクラが実音より下に書かれていた（加線は最大 18 本）。8va も、音部記号の途中変更もなかった

### Verovio で確かめたこと

- **幅と高さ**：「折り返しなし、空の段を隠さない、幅は中身なり」で描ける。高さは全段ぶん
- **段の縦位置**
  - 別々に描いた枠は、段の縦位置がずれる。中身に押されて段の間が広がるため
  - MEI の `staffDef@spacing`（前の段の下端からこの段の上端までの最低の間隔）を書き込むと、その間隔が守られる。間隔を中身より広く取れば、段の位置は完全に一致する
  - MusicXML の `<staff-layout>` は無視される
  - MusicXML → MEI → 書き込み → MEI の読み直しで、手間は 1 枠あたり約 70 ms 増える
- **枠の頭**
  - 音部記号・拍子・楽器名は、`print-object="no"` で幅ごと消える
  - 残るのは、左端に全段を貫く縦線と、小節番号（MEI の `mnum.visible="false"` で消える）
- **つなぎ目**
  - 終わりのないタイ、スラー、8va は描かれない（空のグループになる）
  - 止めていない 8va は、線が描かれないまま音符だけがずれる
  - MEI で `startid` と `tstamp2`、`tstamp="0"` と `endid` を使えば、枠の端までの半分を描ける
  - MusicXML の `id` は、MEI と SVG の id にそのまま残る。松葉は SVG の 3 点の折れ線なので、開き具合を後から書き換えられる
- **8va の段番号**：`<octave-shift>` に `<staff>` を書かないと、最初のパート以外では線だけが出て音符が動かない
- **ずっと前の事実**：曲全体を一度に Verovio に渡すと、読み込みに 187 秒かかった末にメモリが尽きた（[0018](./0018-chunked-render-resident-host.md)）。Codex の試作のパノラマはこの方式だった

## 選択肢

| 案 | 中身 | 退けた理由 / 採った理由 |
| --- | --- | --- |
| A. 今の作りを直す | ブラウザで枠を描き、縦に積む。先読みとズームを足す | 読み直すと描き直し。窓の幅ごとに描き直すのも残る。パノラマに向かない |
| B. 曲全体を 1 段で描く（Codex の試作） | 1 枚の SVG | 20 分の曲でメモリが尽きる |
| C. 画面の大きさに合わせてページを描く | Verovio のページ | ズームや窓の大きさを変えるたびに描き直す |
| **D. サーバで 1 小節ずつ描き、横長の 1 本として並べる** | 段の間隔を全小節でそろえ、つなぎ目の記号を直す | **採用** |

## 決定

### 1. 記譜のオクターヴ（先に入れた）

- 楽器表の `writtenOctave` を「実音から何オクターヴ上に書くか」に改め、向きを直した
  - ピッコロ、シロフォン、チェレスタは −1。グロッケン、クロタルは −2
  - コントラバス、コントラファゴット、バスフルート、バスクラは +1。コントラバスクラは +2
- 段ごとに、使ってよい音部記号とオクターヴ線を楽器表に持たせた（`src/notation/registers.ts`）
  - 音部記号は小節ごとに選ぶ。休みで区切った範囲ごとに、加線の少なさと切り替えの少なさで決めるので、1 音の編集が遠くの記号を動かさない
  - 加線 4 本以上の音には、それを 3 本以内に戻す一番小さいオクターヴ線（8va、15ma、8vb、15mb）を付ける
- 音高はオクターヴ線をかける前の高さで書き、`<octave-shift>` を別に付ける。臨時記号の要否は、表示される位置で判定する

### 2. 1 小節を 1 枠にする

- 枠の MusicXML は、曲の中の位置によらない。小節番号は枠の中で振り直し、表示は隠す（番号はページの欄に出す）
  - 小節を挿入しても、描き直すのは中身が変わった小節だけになる
  - ページ表示は、どの小節線でも折り返せる
  - 音符の数、練習番号、拍子の変わり目で区切る規則は要らなくなる
- 頭の音部記号と拍子は、前の小節から変わるときだけ見せる。楽器名は出さない。強弱・奏法・テンポの言い直しはしない
- 手間は 4 小節の枠の 1.3〜1.55 倍になる（レビューでの実測）

### 3. つなぎ目を直す

- タイとスラーは、外へ出る半分と、外から入る半分を、枠の端まで描く。MEI の `tstamp2` と `tstamp="0"` を使う
  - 終わりのないタイ・スラーは MusicXML に出さない（空のまま消えるうえ、幅が狂う例があった）
- 8va は枠の中で必ず閉じる。続きの枠では数字を消し、線を枠の端までつなぐ（SVG を書き換える）
- 松葉は、枠の端での開きを、松葉全体の中の位置から計算して描き直す（SVG の折れ線を書き換える）
- 左端の縦線を消し、小節番号を隠す

### 4. 段の間隔は、今の楽譜だけで決まる値にする

- 段と段の間に最低の間隔を持たせる（下限）
- 各小節を下限の間隔で一度描くと、中身がそれより広く要る所は、その量をそのまま測れる
  - 測った量は、枠の中身のキーで覚える
- 使う間隔 G は、段の間ごとに「下限と、今の全小節で測った量」の最大。少し切り上げて、細かく揺れないようにする
  - 今の楽譜だけで決まるので、編集の履歴には左右されない。量の大きい音を消せば狭まる
- 表示用には、各小節を G で描き直す。G が下限と同じなら、下限で描いたものがそのまま使える
- G が変わったら、全小節を近い所から描き直す。それまでは、下限で描いたものを出す（段が少しずれる）
- 段 1 の上と、最後の段の下の余白も、今の全小節から計算する。描き直しはせず、画像の縦位置で合わせる

### 5. サーバで描き、覚える

- dev サーバに、Verovio を動かす worker thread を置く。既定は 3 本で、`TAKEMITSU_ENGRAVERS` で変えられる
  - 一定回数描いたら作り直す（WASM のメモリが縮まないため）
  - 落ちたら作り直し、その小節は 1 回だけ描き直す。だめなら「失敗」として出す
- 描くのは、今開いている楽譜だけ。順番は、見えている範囲、再生位置の近く、の順
- キーは、描く中身から自動で作る
  - 含めるもの：MusicXML、つなぎ目の情報、G、描き方の設定、Verovio の版、描く側のコードのハッシュ
  - 手で上げる版はない
- 描いたものは、メモリ（上限つき）とディスク（`.local/engravings/`、上限つき、古いものから消す）に覚える。再起動しても描き直さない
- ブラウザへの渡し方
  - SSE は「新しくなった」と知らせるだけ。中身はページが `/api/notation` で丸ごと取る（音の側と同じ）
  - 画像は `/api/engraving/<key>.svg`。中身で決まるので `immutable`
  - 位置の情報（小節の左右端、拍 → x）は `/api/engraving/<key>.json`

### 6. 表示

- **横長の 1 本**：小節の画像をすき間なく横に並べたもの
  - 左端の欄に、楽器名、括弧、今の音部記号
  - 上の欄に、小節番号、練習番号、拍子、テンポ
- **パノラマ**：折り返さずに横へ流す。再生中は、再生線が左から 1/3 に来るように滑らかにスクロールする
- **ページ**：画面の幅で、小節線で折り返して段にし、縦に並べる
  - 再生位置が次の段へ移ったときに送る
  - 段の中で見ていた縦の位置（低音の段を見ていた、など）は保つ
  - 1 小節が画面より広いときは、その段だけ横にはみ出す
- **ズーム**
  - 既定は「高さに合わせる」。欄や操作部を除いた高さに、全段を収める
  - Cmd+= / Cmd+− / Cmd+0（高さに合わせる）、ピンチ、Cmd+ホイール。ポインタか再生線の位置を保つ
  - 縦のスクロールは自由。再生中も縦の位置は戻さない
  - 窓の大きさが変わったとき、「高さに合わせる」なら合わせ直し、手で決めた倍率ならそのまま
- **再生線とクリック**
  - 秒 ↔ 四分音符はテンポ表（`src/score/timeline.ts` の `quartersAt` / `secondsAt`）で変換する
  - 四分音符 ↔ x は、描いたものの位置の情報で変換する。1 つの拍には x を 1 つ（一番左の符頭）。左へ戻る点は捨てる
  - 鳴っている音符の着色はやめる（余湖さんの判断）
- **全画面**：F で集中表示にする。サイドバー、ツールバー、ミキサー、メッセージを隠し、ブラウザも全画面にする。戻ると、入る前の表示に戻る
- **Cmd+B** でサイドバーを開閉する
- **置く画像の数**：DOM に置くのは、見えている範囲と前後の画面ぶんだけ。再生の向きに数画面ぶん先読みする

## 理由

- 描くのをサーバで先に済ませれば、飛んだ先は画像を置くだけになる。ズームと窓の大きさは画像の拡大縮小で済み、描き直さない
- 1 小節の枠と、位置によらない中身により、編集で描き直す量が変わった小節だけになる
- 段の間隔を今の楽譜だけで決めれば、同じ楽譜はいつも同じ見た目になる。覚えたものも再起動後に当たる
- ブラウザは画像を並べるだけになり、Verovio、幅ごとの描き直し、worker の作り直しが消える

## 結果と副作用

- 冷えた状態で開くと、各小節を 2 回描く（下限の間隔で 1 回、G で 1 回）。20 分のダミー曲では数分かかる
  - 最初の画面は下限で描いたものがすぐ出る。段が少しずれるが、そのあとそろう
  - 2 回目からはディスクに覚えたものを使う
- 全段を常に出す。空の段は隠さない。段が多い曲を高さに合わせると小さくなるので、読むときは拡大して縦にスクロールする
- ブラウザで音符を着色しなくなる
- Sibelius への書き出しは、オクターヴの向きと 8va が変わる
  - 下段の 8vb は、Sibelius が音符を元の位置のまま残すことが分かっている（[`../research/sibelius-musicxml-import.md`](../research/sibelius-musicxml-import.md) §2.5）
  - 書き出しを作るときに扱いを決める

## 追記: ページ表示はやめた（2026-09-27）

余湖さんの判断で、ページ表示（画面の幅で折り返した段）をやめ、パノラマだけにした。

- 滑らかなピンチで拡大縮小できるようになり、読むときは拡大してパノラマを流せば足りた
- 空の段をページごとに隠す案は、段をそろえる仕組み（全小節で同じ段・同じ間隔）とぶつかり、ページの区切りも画面の幅で決まるので、作りが大きく複雑になる。見送った。これがなければページ表示を残す理由も薄い
- 表示が 1 通りになり、折り返し、ページ送り、段ごとの左端の欄が要らなくなった

あわせて、「高さに合わせる」の下限を五線 1 段 3 px から 1 px にした（112 段のダミー曲でも全段が欄に収まる）。
