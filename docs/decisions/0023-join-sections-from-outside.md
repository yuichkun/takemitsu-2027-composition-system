# 0023. セクションは別々のコードのまま、曲の一番上の操作でつなぐ

- 状態: 採用（方向。細かい既定は、4 つのアイデアでの試しのあとで見直す。セクションをスケッチそのものにする進め方は [0026](./0026-sections-are-sketches.md)）
- 関係する論点: Q11（形式をどう表現するか）

## 背景

仮の一曲（`pieces/trial/`）は、全セクションが同じ線の部品で書かれていた。線が曲の初めから終わりまで一本の流れとして続き、セクションは規則の替わり目として現れる。
つなぎ目はなめらかになったが、音楽としてはモノリシックで、冗長さを加減しにくく、突然の休止のような非連続も入れにくかった。

余湖さんと決めたこと（2026-09-29）: セクションはそれぞれ自由に作る。すると、別々のコードで書いたセクションどうしを、
重ねる、奏者ごとにずらす、値を続ける、といったつなぎ方で実際にどうつなぐかが問題になる。
余湖さんが確かめたかったのは二つ。どんなセクションどうしでもつなげられるか（つながりを考えずに素材だけ先に作っても安全か）。
曲全体を見ながら、つなぎ方（長さ、どうつなぐか、一度に切り替える、全休止）を調整できるか。

## 選択肢

1. **モノリシック**: 全セクションを一つの部品（エンジン）の値違いとして書く。状態を共有するので、どこでも自然に続けられる。セクションは自由に作れない
2. **別々のまま、出力だけを編集する**: 各セクションを書いたあと、音符を切る・置く・移高する。セクションには何も求めない。値を続けること（次の起点を前の音にする）はできない
3. **別々のまま、入出力の形と一番上の操作でつなぐ**: 2 に加えて、次のセクションのつまみに前の出力から値を入れる。セクションは任意で区切りの候補を出す

## 決定

3 にする（余湖さん「方向性はとても良さそう」、2026-09-29）。

- セクションは今のスケッチそのもの（楽譜をまるごと返す。パートが声部）。入れ子のノードも使える。隣を知らない
- セクションが守ること: 値はつまみにする（あとで外から入れられる）。自分の拍の分け方で書く。できれば区切りの候補（`seams`）を書く
- 一番上の操作は一度だけ書き、どのセクションにも使う（[`../../src/sketch/join.ts`](../../src/sketch/join.ts)）。セクションのコードには入らない
- 配器（声部をどのパートが弾くか）は一番上で決める。セクションの楽器は既定の割り当てになる
- 区切りの候補は必須にしない。書かなければ音の頭で切る
- 重なる所は同じテンポか、1:2 のように拍の分け方が崩れない比にする
- 入れ子の仕組み（`src/sketch/nest.ts`）の上に足す。作り直さない

## 理由

- 「セクションは自由に作る」と両立するのは 2 と 3。値を続けられるのは 3 だけ
- つなぎ方が一番上の値（つまみ）になるので、曲全体を見ながら、つなぎ目ごとに長さややり方を替えて聴き直せる
- 今のスケッチもパレットも、中身を直さずにセクションとして読める

## 結果と副作用

- 一番上はセクションの中の論理を知らない。入出力に載らないもの（和音の積み方の順番など、つまみになっていない値）は続けられない。要るときは、そのセクションにつまみを足す
- 前の出力から値を入れると、セクションが前提にしていた音域を外れることがある（試しでは、一番上でオクターブを動かして収めた）
- 試しと、そこで分かった足りないことは [`../worklog/2026-09-29.md`](../worklog/2026-09-29.md) の「セクションをつなぐ仕組み」
