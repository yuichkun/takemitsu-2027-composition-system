# 0009. 規定適合は自動検査ではなく、提出前の点検で担保する

- 状態: 採用
- 関係する論点: なし

## 背景

応募規定に合致せず受理されない応募が毎年数件発生している
（[`../research/takemitsu-award-2027.md`](../research/takemitsu-award-2027.md)）。
編成の人数、演奏時間、記譜言語、匿名性は、いずれも機械的に検査できる項目である。

このため、保存のたびに規定適合を検査する仕組み（規定リンター）を提案した。

## 選択肢

| 案 | 中身 | 効いてくること |
| --- | --- | --- |
| A. 規定リンター | 保存のたびに全項目を自動検査する | 違反が常に即座に分かる。作って保守する対象が増える。**1回しかない提出のために常時動く仕組みを持つことになる** |
| B. 提出前の点検 | 最終稿に対して、人間と Claude で一度きちんと点検する | 仕組みを作らない。点検が実際に行われることに依存する |
| C. 何もしない | | 不受理のリスクを負う |

## 決定

B を採る。**規定リンターは作らない。**
提出前に、[`../competition.md`](../competition.md) の点検表に沿って人間と Claude で一度点検する。

## 理由

- **提出は1回しかない事象であり、継続的なリスクではない。**
  常時動く検査機構は、この性質に対して過剰
- 検査項目は既に [`../competition.md`](../competition.md) に列挙されている。
  点検表として使えるので、新たに作るものがない
- 作らないと決めた分の労力は、作品そのものに向く

## 結果と副作用

- **点検が実際に行われなければ、何の担保にもならない。**
  最終段階の工程として明示的に置く必要がある
- 提出直前に違反が見つかった場合、修正の時間が残っていない可能性がある。
  → **点検は最終稿の完成時ではなく、浄書に入る前にも一度行う**
- 編成の上限（打楽器4奏者、キーボード2奏者など）は作曲中に常に意識しておく必要がある。
  機械が教えてくれない
