# 0008. 四分音を系全体の前提として設計する

- 状態: 採用
- 関係する論点: Q1 / Q5 / Q6 / Q12

## 背景

作品は**四分音までを使う**。これは作曲上の与件であって、技術的な選択ではない。

決めるべきなのは、この与件をシステムのどの層で引き受けるか。
音楽ソフトウェアの既定は半音単位の整数（MIDI ノート番号）であり、
四分音はその外側にある。

## 選択肢

| 案 | 中身 | 効いてくること |
| --- | --- | --- |
| A. 半音のモデルに注釈として乗せる | 音高は整数のまま、四分音を「ずらし」の属性として付ける | 既存の枠組みをそのまま使える。**射影・プレビュー・変形のすべてで例外処理が発生し、抜けが出る** |
| B. 音高モデルを最初から微分音対応にする | 音高表現そのものを半音整数にしない | すべての層が一貫して扱える。音高表現の設計を最初に決める必要がある |

## 決定

B を採る。**音高表現を半音単位の整数にしない。**
具体的な形式（セント値 / 有理数 / 24平均律の整数 / その他）は [Q6](../open-questions.md#q6) で決める。

あわせて、**四分音を扱えることを音源選定の第一条件にする**（[Q1](../open-questions.md#q1)）。
四分音を出せない音源は、他がどれほど優れていても候補から落ちる。

## 理由

- 四分音は例外ではなく常用される。例外処理として扱うと、例外のほうが多数になる
- 波及範囲が広い。データモデル、MusicXML 射影、MIDI 射影、譜面プレビュー、変形の語彙の
  すべてが音高表現に依存する。**後から変えると全体に及ぶ**
- 音源が四分音を出せなければ、レンダリングは作品と別の音を鳴らすことになり、
  [判断のための装置](../proposal.md#高品質再生は贅沢ではなく認識論的な必要条件)として機能しない

## 結果と副作用

- **MIDI 射影が複雑になる。** ノートごとのピッチベンドを使う場合、
  1ノート1チャンネルの割り当て管理が必要になり、楽器数 × ポリフォニーで
  チャンネルが枯渇しうる。MTS-ESP や Scala などのチューニング標準が使えるなら回避できる
- **MusicXML 射影と Sibelius の取り込みが未知数になる。**
  四分音の臨時記号がどこまで渡るかを実機で確認する必要がある（[Q12](../open-questions.md#q12)）
- **譜面プレビューが四分音の臨時記号を描ける必要がある。** 選定条件が増える（[Q5](../open-questions.md#q5)）
- 音源の選択肢が狭まる。物理モデリング系が有利になる可能性がある
